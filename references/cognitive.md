# 第 3 层｜认知引擎（Cognitive Engine）

这一层不问"怎么排"，问**"学生在这一页要发生什么"**。
同一段内容，认知目标不同，视觉表达就该完全不同。

---

## 一、九种认知动作

spec 里写 `page.cognitive`，英文 id 或中文都行。

| id | 中文 | 学生此刻 | 视觉任务 | 优先版式 |
|---|---|---|---|---|
| `curiosity` | 好奇 | 咦？为什么会这样 | 给一个**具体的反差**，不给结论 | bigIdea / fullImage / caseStory / cover |
| `prediction` | 预测 | 我觉得是 A | 摆出选项，让他先下注 | question / debate |
| `conflict` | 冲突 | 我原来想错了 | 并置"以为的"与"实际的" | debate / matrix / caseStory |
| `explanation` | 解释 | 原来是因为这个 | 一条因果链，不要罗列 | causalChain / layers / flow |
| `concept` | 概念 | 这个现象叫「职权」 | 定义 + 特征 + 边界，三件齐 | layers / bento / matrix |
| `evidence` | 证据 | 有数据，我信了 | 图或案例结果，指向一个结论 | dataChart / caseStory / zoom |
| `application` | 应用 | 换我会怎么做 | 给情境，让他做决定 | question / flow / bento |
| `transfer` | 迁移 | 换个行业还成立吗 | 换角色/换规模/换行业 | debate / offsetImageText / matrix |
| `reflection` | 反思 | 回头看，我哪里想错了 | 回到开场的那个判断 | summary / bigIdea / question |

**一页只做一个动作。** 想在一页里既解释又让学生做题，结果是两件都没做透。

引擎会检查：未标注的页数、连续三页同动作、关键动作缺失（`prediction`/`conflict`/`application`；
≥12 页还要 `transfer`）。

## 二、五类知识 → 五种视觉语法

认知科学里，知识类型不同，表征方式就该不同。照抄"三段式卡片"是知识类型不清的表现。

| 知识类型 | 特征 | 该用什么视觉 | 别用什么 |
|---|---|---|---|
| **概念性**（职权、集权） | 有定义、有边界、易与近邻概念混 | 分层（定义/特征/边界）、二维矩阵（与近邻区分） | 流程图（概念不是过程） |
| **程序性**（授权六步、控制四步） | 有顺序、有判断点、有产出 | 流程（带产出标签）、编号列表 | 四张平行卡片（丢了顺序） |
| **关系性**（集权与分权、责与权） | 两两对立、互相制约、有权重 | 对照（左右）、因果链、矩阵 | 单列要点（体现不出张力） |
| **叙事性**（一个案例、一次事故） | 有时间线、有人、有转折 | 时间轴、四幕案例、全幅图 | 要点罗列（故事被拆碎） |
| **元认知**（我原来怎么想的） | 关于学生自己的判断 | 大字观点、单页反问、前后对照 | 图表（把反思变成数据） |

一句判断：**你这一页的知识，是"是什么"、"怎么做"、"谁和谁"、"发生了什么"，还是"你怎么想"？**
答案决定视觉语法，视觉语法决定版式。

## 三、认知负荷：三条硬规律

工作记忆一次只能处理约 4 个组块。超出，学生就只看字不听课。

### 1. 组块律：一页 ≤4 个组块

"组块"不是字数，是**学生要同时握住的信息单元**。
一页 3 个要点 + 1 个结论条 = 4 块，刚好；再加一组数据就超了。

### 2. 分割注意律：图与文不要各自说一件事

图在讲 A、文字在讲 B，学生要在两者间来回切，两边都记不住。
正确做法：**图承担"看见"，文字承担"结论"**，且指向同一件事。

### 3. 冗余律：不要同时"念"和"写"

页面上一整段话 + 教师逐字念 = 双通道抢同一内容，反而降低记忆。
页面写结论（≤30 字），讲稿写推导。

### 页面上可直接检查的阈值

| 指标 | 阈值 | 超了怎么办 |
|---|---|---|
| 每页字数 | 中位 ≤150，单页 ≤260 | 拆页，或把细节移进讲稿 |
| 一页要点数 | ≤4 | 合并，或拆页 |
| 字号种类 | ≤5 | 收敛到六级阶梯 |
| 并列结构（"和/与/、"）在标题里 | 0 | 拆页，或只留一件 |
| 填充率 | ≤55% | 减内容，不是缩字号 |

## 四、最常见的四种"看起来对、其实错"

| 症状 | 真实原因 | 改法 |
|---|---|---|
| 每页都是三栏卡片 | 没判断知识类型，用了默认模板 | 按上表选视觉语法；关系性内容用对照/矩阵 |
| 页面很满但学生记不住 | 组块超 4 | 删到 3 块，把第 4 块移到下一页 |
| 图很好看，但讲不清 | 图与文各说一件事 | 让图只承担"看见"，文字只给结论 |
| 学生听懂了但不会用 | 缺 `application` | 加一页"换你会怎么做"，带判断标准 |

## 五、和版式的关系（别倒过来）

```
知识类型 → 视觉语法 → 认知动作 → 版式 id
```

**不是**"先挑一个好看的版式，再往里塞内容"。倒过来做，就会出现
"用流程图讲定义"、"用四张卡讲有先后顺序的六步"这类结构性错误。

版式清单与字段见 `layouts.md`；页面类型配方见 `layout-library.md`。
