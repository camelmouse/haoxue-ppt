# 第 2 层｜叙事引擎（Narrative Engine）

课堂不是"知识点的容器"，是一条**从困惑走到能判断**的路径。
这一层决定顺序与标题；标题写砸了，后面的版式和配色都救不回来。

---

## 一、六拍（默认主线）

```
真实问题 → 学生判断 → 完整案例 → 理论解释 → 跨场景拓展 → 学习检测 → 一句话收束
```

| 拍 | 目的 | 常用认知动作 | 时长占比 |
|---|---|---|---|
| 真实问题 | 制造"与我有关" | `curiosity` | 10% |
| 学生判断 | 暴露误解，制造冲突 | `prediction` | 10% |
| 完整案例 | 给出可感知的全过程 | `explanation` / `evidence` | 30% |
| 理论解释 | 把案例抽象成机制 | `concept` / `explanation` | 25% |
| 跨场景拓展 | 迁移到不熟悉的场景 | `transfer` | 15% |
| 学习检测 | 检验真的会了 | `application` | 5% |
| 一句话收束 | 留记忆锚点 | `reflection` | 5% |

允许调换顺序（例如先案例后问题），**不允许删掉"学生判断"**。没有判断就没有参与，
学生只会等你给答案。

### 认知动作不是标签，是"该用哪一页"的依据

九种动作与配图方式见 `cognitive.md`；这里只强调一条：
**动作顺序错了，课就拧了。**

- 先 `concept` 后 `conflict`：学生先记住定义，再被推翻，等于白讲。
- 先 `explanation` 后 `prediction`：还没猜，就被解释，学生会觉得"你早说啊"。
- 结尾用 `concept`：课停在知识上，学生不知道这跟他有什么关系。

## 二、标题就是论证（Action Title）

普通课件：

```
PDCA循环          激励理论          组织结构
```

这类标题是**目录**，不是叙事。读者拿不到任何信息：不知道结论、不知道立场、不知道和上一页什么关系。

本 skill 要求标题是一句**判断**：

| 目录式 | 判断式 |
|---|---|
| PDCA循环 | PDCA 解决的从来不是"做计划"，是让错误不再重复 |
| 激励理论 | 员工不努力，未必是因为钱给少了 |
| 组织结构 | 公司越大，信息越容易在传递中失真 |
| 授权的原则 | 授权不是撒手，是把边界先写清楚 |

写法只有三种，选一种：

1. **不是 A，而是 B**（纠错）——适合冲突页、概念页
2. **因为 X，所以 Y**（机制）——适合解释页、因果链
3. **具体数字 + 反问**（好奇）——适合开场、案例页

长度：**≤20 字**（超过 28 字必然折三行，标题会压住正文）。定语挪到副标题或讲稿。

## 三、Ghost Deck Test（必做）

**做法**：把正文、图片、装饰全部删掉，只留每一页的标题，连读一遍。

```bash
python scripts/ghostdeck.py examples/management-authority-v2.deck.json
python scripts/ghostdeck.py out/deck.pptx        # 从成品反推
```

**判据**：

- 读下来能讲清整堂课的逻辑 → 结构通过（≥75 分）
- 读下来是「管理概念 / 管理职能 / PDCA / 案例分析 / 小结」→ 这只是目录，不是教学叙事

**脚本查什么**：

| 检查项 | 扣分力度 | 含义 |
|---|---|---|
| 目录式标题占比 >18% | 致命 | 只给名字不给结论 |
| 无判断信号的标题 ≥25% | 致命 | 没有对比/因果/否定/数字/提问 |
| 相邻两页标题相似 >0.62 | 致命 | 两页在说同一件事 |
| 单行 >28 字 | −12%/页 | 会折三行 |
| 标题并列两件事 | −10%/页 | 该拆页 |
| 冲突页在预测页之前 | −4 | 学生还没判断就被纠正 |
| 结尾不在反思/收束 | −5 | 叙事没闭合 |

**不合格怎么改**（脚本会指出具体页号）：

- 目录式 → 补上"和什么比、为什么、结果是什么"
- 无判断 → 加一个具体数字或一个反问
- 相邻重复 → 后一页换个动作（解释完 → 给证据 / 让学生用一次）
- 超长 → 压到 20 字，定语下沉

## 四、节奏：什么时候要"停一下"

连续讲三页以上，学生的注意力会掉。停的方式有三种，作用不同：

| 手段 | 效果 | 用在哪 |
|---|---|---|
| 章节分隔页（`divider`） | 深吸一口气，知道要换话题 | 每 5–7 页一次 |
| 大字观点（`bigIdea`） | 砸一下，全场只看一句话 | 一章一次，放在章的结论处 |
| 全幅图（`fullImage`） | 停两秒，让画面说话 | 案例转折处、情绪最强处 |

经验值：**每 4–5 页必须有一次强度变化**。90 分钟的课，至少 3 次。

反过来，节奏不能全是"停"：如果每页都是大字或全幅图，就没有内容承载，学生会觉得"这课很水"。

## 五、按课程类型调整

| 课程类型 | 开场 | 主体偏好 | 要特别小心 |
|---|---|---|---|
| 概念/原理课 | 反直觉现象 | `concept`→`explanation`→`conflict` | 别用流程页讲原理，学生只记步骤不记原因 |
| 操作/实训课 | 一次失败的操作 | `application` 为主，步骤必须可复现 | 参数、工具、判断点不能省 |
| 案例分析课 | 一个决策困境 | `curiosity`→`prediction`→`explanation` | 案例要有"当时不知道结局"的紧张感 |
| 数据/营销课 | 一个反常数字 | `evidence`→`explanation`→`transfer` | 图表必须指向一个结论，不是展示数据 |
| 医学/解剖课 | 一个症状或影像 | `zoom` / `fullImage` / `layers` | 结构必须专业准确，示意图要标"示意" |
| 人文/思政课 | 一个具体的人 | `explanation`→`debate`→`reflection` | 避免口号堆叠，用细节支撑观点 |

## 六、讲稿（notes）写什么

页面给结论，讲稿给推导。写四件事，不要抄页面上的字：

1. **这一页要让学生想什么**（一句话）
2. **教师追问**（如果学生答 X，就追一句 Y）
3. **学生可能的错误回答**，以及你怎么接
4. **过渡句**：讲完这页，下一句怎么带到下一页

长度：3–6 句。写成长篇讲稿的，说明这一页塞了太多东西，应该拆页。

## 七、自查

- [ ] Ghost Deck ≥75 分，无目录式标题
- [ ] 每页标题 ≤20 字，且是判断句
- [ ] 认知动作顺序没有"先概念后冲突"
- [ ] 结尾回到开场的问题（`reflection` 或 `summary`）
- [ ] 每 4–5 页有一次强度变化
- [ ] 讲稿写了追问与过渡，不是页面的复述
