# 第 6 层｜PPTX 引擎（PPTX Engine）

这一层是发动机，不是驾驶员。**教学层决定做什么，这一层决定怎么落到文件上。**

---

## 一、三条路，先选对

| 任务 | 用什么 | 不要用 |
|---|---|---|
| **新建**一份课件 | PptxGenJS（`scripts/build.js`） | 手写 OOXML |
| **改**已生成的成品（改色、加阴影、修裁切） | OOXML 后处理（JSZip + 正则/XML） | 重新生成整份 |
| **读**别人的文件（分析、抽 DNA、质检） | python-pptx（结构）+ 渲染（视觉） | 靠猜测 |

铁律：**新建走生成器，改走 OOXML，读走 python-pptx。** 三者混用是最常见的塌方来源
（比如用 OOXML 去"新建"页面，或用渲染图去"读"字号）。

---

## 二、内容源在 spec，不在 PPTX

```
spec.json → build → pptx → render → qa
   ↑                                    ↓
   └──────────── 改内容改这里 ←──────────┘
```

发现问题时**改 spec 再构建**，不要手改成品页。手改会让下一次构建把你的修改覆盖掉。

单页迭代的正确姿势：

```bash
node scripts/build.js <spec> -o out/p8.pptx --only 8     # 只重建第 8 页
python scripts/splice.py out/deck.pptx out/p8.pptx 8 -o out/fixed.pptx
```

`splice` 保留原页码与其余页，所以页脚仍是 `08 / 40`。

例外：用户明确要求"保留原 PPT、只改某几页排版"时，走 OOXML 直接改那一页
（见下节），并在交付时说明"此页已脱离 spec，后续重新生成会覆盖"。

## 三、OOXML 后处理：为什么必须做

pptxgenjs 有两个硬限制：

1. `fill` 只支持**纯色**，不能给形状上渐变；
2. 阴影只能有一层，做不出"接触阴影 + 环境阴影"。

一眼看过去"平"，往往不是配色问题，而是所有东西贴在同一个平面上。补法是 `postprocess.js`：

| 层 | 做法 | 实现 |
|---|---|---|
| 填充 | 上亮下暗的极轻渐变（按底色亮度提亮 12%–55%） | 给 `name="card.*"` 的形状注入 `a:gradFill` |
| 接触阴影 | 模糊 38100、偏移 19050、alpha 18% | 注入第一个 `a:outerShdw` |
| 环境阴影 | 模糊 330200、偏移 120650、alpha 12% | 注入第二个 `a:outerShdw` |

约束：

- 方向固定 `5400000`（90°，光从正上方）
- **只有显式声明 `shadow` 的对象才有影子**——给所有矩形都加阴影，脏得比平更糟
- 深色主题自动关阴影（深底上阴影不可见，只留灰边）
- 遮罩用**一条带 alpha 停靠点的纵向 `gradFill`**，不要用分段半透明矩形（会出"梯田横纹"）

### 三个踩过的坑（改这块代码前先读）

| 坑 | 症状 | 根因 |
|---|---|---|
| require 路径错 | 渐变全没生效，但没有任何报错 | `lib/` 内写成 `./lib/color`，异常被吞 |
| 孤立 `<p:spPr>` | PowerPoint 提示文件损坏 | 正则拼回时把开标签切掉了 |
| 强调条露头 | 圆角处出现直角小方块 | 强调条两端没按 radius 内缩 |

第一类最危险：**后处理失败必须留痕**（`result.postError`），否则"立体化没生效"会静默发生。

## 四、字号工程：字号不是审美，是约束

| 规则 | 落地 |
|---|---|
| 六级阶梯 52 / 34 / 26 / 21 / 18 / 16 | `design.js` 的 `TYPE`，相邻比 ≥1.12 |
| 任何文字 ≥16pt | `MIN_FONT=16`，在 `measure` / `canvas` / `fitText` / `qa` 四处同时卡 |
| 一页 ≤5 种字号 | `FONT_KINDS_MAX=5` |
| 放不下就删字，不缩字 | `fitText()` 只会**向上**取阶梯值；取不下报 `DOC-DENSE` |

`fitText(text, w, maxH, {max, min})` 的行为：
在阶梯上从 `max` 往下试，找到第一个能放进 `w × maxH` 的字号；全部放不下时返回**最小档**
并让调用方决定（通常是报警，而不是继续缩）。

为什么卡在四处而不是一处：`canvas.text()` 是最后一道闸，但版式里会先算高度、
先做折行，如果那些地方用小字号算过，到 canvas 再抬回 16pt 就会溢出。

## 五、原生可编辑的边界

| 元素 | 在 PowerPoint/WPS 里能做什么 | 备注 |
|---|---|---|
| 文字 | 改字、改字号、改色、拖动 | 是真文本，不是图片 |
| 形状 | 改填充、改边框、改圆角、调层级 | 后处理注入的渐变也能在"设置形状格式"里改 |
| 图表 | 右键"编辑数据" | 原生 chart，但不内嵌 xlsx（见限制） |
| 图标 | 改色、缩放 | Lucide 转 SVG 路径，不是字体图标 |
| 图片 | 裁切、替换 | 已做等比裁切修正 |
| 遮罩 | 可调透明度 | 是 gradFill，不是半透明色块叠层 |

不允许出现：整页截图、把文字转成图片、把图表贴成 PNG。
一旦这么干，用户想改一个字都得重做，skill 的价值就没了。

## 六、已知限制（交付时要主动说）

1. **图表不内嵌 xlsx**：右键"编辑数据"能改，但不能"编辑数据→打开 Excel 工作簿"。
2. **本机无 PowerPoint/WPS 时的兼容性证据**来自 python-pptx 解析 + Spire 渲染，
   不等于在真机上打开过。交付时说明"已通过渲染校对，请在目标机器上过一眼"。
3. **Spire 预览会裁掉约 5% 的顶部条**（水印区），不要据此判断顶部装饰错了。
4. **`DENSITY` 不计纯文字密度**：一段没有卡片承载的大段文字，填充率可能仍显示正常。
5. **bento 只支持 3–6 格**：7 格以上请拆页或换 `flow`。
6. **渐变是后处理注入**：用第三方工具把 PPTX 转成别的格式（如转 PDF 再转回）时，
   渐变可能被压平。
