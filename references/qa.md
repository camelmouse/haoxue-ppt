# 质检：16 项自动检查、怎么修、以及已知限制

```bash
python scripts/qa.py out/deck.pptx                        # 结构检查
python scripts/qa.py out/deck.pptx --strict                # 有 error 时退出码 1（CI 用）
python scripts/qa.py out/deck.pptx --json out/qa.json      # 机读
python scripts/render.py out/deck.pptx -o out/preview      # 先渲染
python scripts/qa.py out/deck.pptx --preview out/preview   # 结构 + 渲染交叉检查
```

报告分三级：`必须修复`（error）/ `需人工确认`（warn）/ `提示`（info）。
**交付标准是 0 个必须修复、0 个需人工确认**；提示可以留。

---

## 一、16 项检查

| # | 代码 | 查什么 | 判定依据 |
|---|---|---|---|
| 1 | `BOUNDS` | 元素越出页面 | 画框超出 13.333×7.5；装饰圆允许出血（标 `decor.*`） |
| 2 | `OVERFLOW` | 文本溢出文本框 | 按字符宽度估算（CJK 1.0em / 全角标点 0.92em / ASCII 0.55em，行高 1.32） |
| 3 | `IMAGE` | 图片拉伸/缺失 | 画框宽高比与原图差异 > ±1.5%（写了 `srcRect` 裁切的跳过） |
| 4 | `OVERLAP` | 文本块异常重叠 | 两文本块重叠面积 > 阈值（先按估算字宽收窄再算） |
| 5 | `FONT` | 字号过小 / 种类过多 | 任意文字 **< 16pt 报错**（正文、辅助、页码一律不例外）；一页字号种类 > 5 提醒 |
| 6 | `CONTRAST` | 文字与底色对比度 | 正文 < 4.5:1 报错；大字 < 3.2:1 提醒 |
| 7 | `CHART` | 图表数据与标签不一致 | 分类数 ≠ 各类数值数、或分类标签为空 |
| 8 | `NAV` | 导航缺失/重复/越界/序号不符/章节倒退 | 内容页必须有且只有 1 个当前章节标记，位置在右上角；章节序号随页序单调不减 |
| 9 | `PLACEHOLDER` | 残留占位文字 | `TODO`/`XXX`/`lorem`/`占位`/`待补` 等 |
| 10 | `REPEAT` | 版式过度重复 | 连续 3 页以上同一版式 |
| 11 | `FILE` | 文件结构完整性 | 能否被 python-pptx 打开、页数是否 > 0 |
| 12 | `RENDER` | 渲染结果非空白 | 灰度标准差过小视为空白页（需 `--preview`） |
| 13 | `DENSITY` | 页面填充率过高（留白不足） | 色块/图片/图表按 96×54 栅格求并集，覆盖 > 55% 提醒。文字框不计入（文字是内容不是底色） |
| 14 | `SHADOW` | 阴影方向不一致或过重 | 光源角度偏离向下 90° 超 ±15°、或不透明度 > 26% |
| 15 | `HIERARCHY` | 标题与正文层级差不足 | 最大字号 / 正文字号中位 < 1.5（"看不出重点"） |
| 16 | `MARGIN` | 元素贴页边 | 正文元素距任意页边 < 0.5in；页眉/页脚/导航/铺底元素豁免 |

13–16 是「旁门左道」排版方法论的量化版本，阈值与 `scripts/lib/design.js` 一一对应：
`DENSITY_MAX` / `SHADOW.angle` / `HIER_RATIO` / `MARGIN_MIN`。

辅助元素的判定：名字匹配 `^(footer|page\.|nav\.|caption|source|decor|credit|note\.|aux\.|meta\.)`
的文本框自动按"辅助信息"处理（辅助信息同样不得低于 16pt，只是不参与正文层级统计）。
铺底元素的判定：名字匹配 `^(bg|scrim|decor)` 或面积超过整页 60% 的形状，不参与 `DENSITY` 与 `MARGIN`。

## 二、常见报错怎么修

| 报错 | 原因 | 改法 |
|---|---|---|
| `TEXT-OVERFLOW` | 一页塞太多字 | 缩短文案 / 拆页（首选）；或给该 `cv.text` 传更小 `size` |
| `字号 11pt 低于下限 16pt` | 手写了小于阶梯的字号 | 用 `SCALE` 里的值（16 / 18 / 21 / 26 / 34 / 42 / 52）；空间不够就删字、拆页，**不要缩字号** |
| `对比度 2.1:1` | 用了 `primary`/`accent` 原色当正文色 | 改用 `primaryText`/`accentText`（已自动压深到可读） |
| `图片比例可能被拉伸` | `cover` 裁切未写 `srcRect` | 走 `cv.image(..., {fit:'cover'})`，`cropfix` 会自动补 `<a:srcRect>`；`zoom` 页由引擎预裁切 |
| `缺少进度导航` | 该页 `chapter` 不在 `chapters` 里 | 补 `chapter` 字段，或写 `"nav": "hidden"` 显式关闭 |
| `同一页出现 2 个当前章节标记` | 手写了导航文字 | 删掉手写导航，交给 `nav.js` |
| `章节序号倒退` | 某页 `chapter` 落到了更靠前的章节 | 检查该页 `chapter`，页序要与章节顺序一致 |
| `胶囊导航当前项数量异常` | `nav.tabs.*.on` 不止一个 | 只由 `nav.js` 绘制，不要手改 |
| `刻度数 5 与章节总数 4 不一致` | 改了 `chapters` 没重新生成 | 重新 `build` |
| `图表分类与数值数量不一致` | `chart.series[].values` 与 `categories` 长度不等 | 补齐或删掉多余数据 |
| `疑似占位文字` | 文案里留了 TODO | 写完再交付 |
| `页面填充率 68%（建议 ≤55%）` | 页面上色块/图片铺太满 | 缩色块、加间距（用 `SPACE` 档位）、或把内容拆到下一页 |
| `阴影方向 0°（应统一向下 90°）` | 手写了 `angle` | 用 `shadow: 'sm' / 'md'` 档位，不要自己写对象 |
| `阴影不透明度 100%` | 阴影对象没有 `opacity` | 同上，走 `design.SHADOW` |
| `层级差不足：最大 21pt / 正文 21pt` | 标题和小标题一样大 | 拉开到 `TYPE` 阶梯（如 34 / 21 / 16） |
| `一页出现 6 种字号` | 同一页手写了多套字号 | 收敛到 ≤5 种：层次靠字重、颜色、留白拉，不靠多给字号 |
| `元素贴边：xxx 距左边 0.43in` | 装饰元素误用了正文坐标 | 装饰命名 `decor.*`；正文回到 `MX = 0.85` |

## 三、已知限制（诚实清单）

1. **文字度量是估算模型**，不是真实字体排版。安全余量较大，但极端窄框仍可能误判；
   最终以渲染图为准（`render.py` + 人眼）。
2. **中文断行禁则由渲染器决定**。引擎按禁则做度量与预判，但 PowerPoint/WPS/Spire
   各自断行略有差异，可能出现"」"落在行首。PowerPoint 与 WPS 的禁则支持较好，
   Spire（本仓库渲染预览用）较弱。
3. **`zoom` 放大图**：靠 `sharp` 预裁切。未安装 sharp 时退化为整图填充（会拉伸），
   此时质检会提示需人工确认。
4. **图片裁切**：`<a:srcRect>` 在 LibreOffice 上支持有限，PowerPoint/WPS 正常。
5. **渲染预览用 Spire 评估版**：单册 10 页限制由 `render.py` 拆册绕过，并在裁切时
   去掉顶部 5% 评估水印。**这只影响本地预览，不影响交付的 .pptx**。
6. **局部修改**：`--only` 只重建指定页，再用 `scripts/splice.py` 在 OOXML 包级别
   把这一页换回整套（页序、页码、其余页字节不变）。它逐层克隆 slide part 及其
   图片/图表/备注关系并保持 rId 不变，因此不会出现"图挂了"的经典坑。
   限制：不处理 PowerPoint 的「节」归属；带超链接指向其他页时需人工复核。
7. **字体**：默认微软雅黑（Windows 必备）。macOS/Linux 上会被替换，度量会有偏差，
   交付给 Windows 用户最稳。
8. **图表数据表**：引擎生成的图表在 PowerPoint 里可"编辑数据"，但它不内嵌 xlsx，
   首次编辑时 PowerPoint 会现场创建数据表。
9. **`DENSITY` 只统计实心块/图片/图表**，不含文字框。所以"文字密集但无底色"的页面不会被它抓到，
   这类问题由 `OVERFLOW` / `OVERLAP` / `HIERARCHY` 兜。它是"版面被色块压满"的报警器，不是万能密度计。
10. **`MARGIN` 靠命名区分装饰**。新增版式时若在页边放装饰元素，名字必须以 `decor.` 开头，
    否则会被判为"正文贴边"。

## 四、自检脚本（生成层）

```bash
node tests/test_skill.js          # 120 项：主题/版式/导航(含胶囊)/图片模式/长文本/局部生成/全主题/设计规则
node tests/test_skill.js --verbose
```

它不依赖 Python 与办公软件，适合提交前快速回归。
