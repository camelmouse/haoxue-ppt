# 第 7 层｜教学质检（Teaching QA）

不是"好不好看"，是**这堂课立不立得住**。
七维加权，**低于 8.0 分是重做，不是先交付再改**。

```bash
python scripts/teachqa.py out/deck.pptx --spec examples/x.deck.json
python scripts/teachqa.py out/deck.pptx --spec ... --json out/tqa.json
```

---

## 一、七维权重

| 维度 | 权重 | 在问什么 |
|---|---|---|
| 教学逻辑 | 25% | 有没有把学生从"不知道"带到"会用、知道边界" |
| 认知负荷 | 20% | 一页是不是只讲一件事，学生读得完吗 |
| 视觉层级 | 15% | 标题是否明显大于正文，字号守不守下限 |
| 课堂互动 | 15% | 学生有没有"先想一下"的机会 |
| 案例有效性 | 10% | 有没有具体的人、数，以及"这是模拟"的声明 |
| 视觉完成度 | 10% | 版式够不够多样，卡片是否真的"浮起来" |
| 技术合规 | 5% | `qa.py` 的结论（不另造一套标准） |

权重排序说明了立场：**教学逻辑比视觉完成度重要五倍。**
一份排版普通但逻辑扎实的课件，好过一份漂亮但学生学不到的课件。

---

## 二、每维怎么扣分

### 教学逻辑（25）

- 缺 `prediction` / `conflict` / `application`：每个 −1.8（`conflict`、`application` 记"致命"）
- ≥12 页缺 `transfer`：−1.8
- 连续三页同一动作：−1.2
- 前三页没有 `curiosity`：−0.8
- 结尾不在 `reflection` / `summary`：−1.2
- `intent` 缺 `goal` / `misconception`：每个 −0.9；缺 `oneLine` / `boundary`：每个 −0.6

### 认知负荷（20）

- 每页字数中位数 >200：−2.4（致命）；>150：−1.3
- 单页 >260 字：每页 −0.5（上限 −2.0）
- 标题并列两件事：每处 −0.35
- 一页 >5 种字号：−0.4

### 视觉层级（15）

- 标题 <24pt：−0.6/页
- 标题/正文 <1.35：−0.6/页（正文取"比标题小的字号"里的众数）
- 最小字号 <16pt：−3.0（致命）

### 课堂互动（15）

- 0 页 `question`：2.5 分（致命）
- 1 页：6.5 分
- ≥2 页：9.0 分；占比 >35% 再 −1.5（变成刷题课）
- 讲稿里写"提问/让学生/先想"的页 <25%：−1.2
- 互动题没标正确答案：−1.0

### 案例有效性（10）

- 没有 `caseStory`：5.0 分
- 案例有具体数字：+0.5/页（上限 +1.5）
- 有"教学模拟/虚构"声明：+0.8；没有：−1.4（致命）
- 没有适用边界：−1.2

### 视觉完成度（10）

- 版式 <6 种：−1.6
- 连续三页同版式：−1.2
- 有渐变填充的页 <40%：−1.6
- 有阴影的页 <40%：−1.2
- 图片版式没有图：−0.8/页（致命）

### 技术合规（5）

直接吃 `qa.py`：`10 − 3×必须修复 − 0.4×需确认`。有必须修复项记"致命"。

---

## 三、拿到报告先修哪一项

按 **权重 × 与满分的差距** 排序，不要按"看起来最刺眼"修。

```
优先级 = 权重 × (10 − 得分)
```

例：教学逻辑 8.0（权重 25）→ 0.25×2 = 0.50；视觉完成度 6.0（权重 10）→ 0.10×4 = 0.40。
先修教学逻辑。

**致命项永远优先**，不管权重：案例没声明模拟、图版式没图、字号 <16pt，这三类
会让课件在公开场合出事或直接不可用。

---

## 四、三级清单

| 等级 | 含义 | 处理 |
|---|---|---|
| ⚠️ 致命 | 不改不能讲 | 交付前必须清空 |
| ⚡ 重要 | 这次能讲，下次一定改 | 交付时告知用户 |
| 💡 优化 | 可以做，也可以不做 | 记入下次 |

报告里每条都带"为什么"：不是"字太多"，而是"每页字数中位数 174，一页塞了两三件事"。

---

## 五、机器判不了的部分（必须人工看）

`teachqa.py` 评的是可计算的近似。下面这些只能靠眼睛和判断：

1. **版面是否好看**：对齐、呼吸感、装饰是否多余
2. **案例是否可信**：数字是否合理、情节是否像真的
3. **讲稿是否口语**：写的是"要说什么"，还是抄页面
4. **认知动作是否名副其实**：标了 `conflict`，但页面其实在平铺直叙
5. **边界句是否真的成立**：技术上写了一句"不适用"，逻辑上是糊弄

对应做法：`render.py` 出图 → `sheet.py` 拼总览 → 按缩略图逐页看 →
可疑页放大看 → 至少看完首屏 3 页 + 所有特殊版式页。

**脚本通过 ≠ 可以交付。** 这一点写进 SKILL.md 的硬约束第 12 条。

## 六、和 qa.py 的分工

| | `teachqa.py` | `qa.py` |
|---|---|---|
| 管什么 | 教学：逻辑、负荷、互动、案例、层级 | 技术：越界、重叠、字号、对比度、导航、密度 |
| 依据 | spec（认知动作、intent）+ pptx | pptx（几何与样式） |
| 输出 | 七维评分 + 三级清单 | 必须修复 / 需确认 / 提示 |
| 门槛 | ≥8.0 | 0 必须修复 |

两者不重叠：`teachqa` 饿的时候会去调 `qa.py` 拿技术分，但**不重复实现**它的检查。

---

## 七、评分不达标时的处理顺序

1. 先清致命项（案例声明、缺图、字号下限）
2. 再按"权重×差距"修两维
3. 重跑，看总分是否过 8
4. 若卡在 7.5–7.9：通常是"认知负荷"与"课堂互动"两项虚低——
   拆 2–3 页最挤的页、加 1 页真问题，通常就够了
5. 修完仍不过：**改内容，不是改分数**。不要为了过评分去砍掉必要的内容或硬加互动页。
